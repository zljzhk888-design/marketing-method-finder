# 简洁图文分析网页

在分析有初步结论后读取本规范。目标是让用户在一分钟内理解“先做什么、为什么、如何开始”，需要时再展开细节。

## 交付

- 每次分析默认生成实际网页文件或托管网页，不把 HTML 代码块当作交付物。不自动创建一个供用户填写资料的新 SaaS 产品。
- 有可用的网站生成 skill（例如 Sites）时，读取并使用其工作流完成生成、预览与交付，遵循其发布和访问控制规范。用户要求本地文件时采用本地方式。
- 没有可用网站工具时，在当前可写工作目录的 `output/marketing-analysis/<业务短名>/index.html` 创建自包含网页，并返回绝对路径的可点击文件链接。保留已有分析，避免覆盖无关文件。
- 简单报告用原生 HTML/CSS 与少量 JS；不为展示静态结论引入登录、数据库、API 或大型框架。内联 SVG/CSS 图示可离线显示，无需外部图片服务。

## 页面结构

默认采用以下阅读顺序，根据业务裁剪，避免凑满模块：

1. **一句结论**：产品名、当前优先方法、一个理由。资料不足时，紧邻结论标注“初步判断”，并简述关键假设。
2. **关键图示**：展示客户从发现到获得价值的路径，突出当前需要验证的环节。没有实际数据时用定性路径图，标注“待验证”；不得绘制虚构转化率或用柱长暗示量化差异。
3. **推荐打法**：一个主方法，至多两个必要配套。每项用短标题、一句理由和相关场景插图/示意图解释；写明适用前提。
4. **第一轮实验**：用三步时间线或流程图呈现动作、投入上限、观察窗口及核心指标。继续/调整条件放在附近；建议规模标明是实验设计，不能伪装成预测结果。
5. **下一步**：展示匹配的可用 skill 与交付物。待补充问题、假设、依据和来源放在末尾，可用原生 `details` 展开。

主阅读路径中文正文以约 400–700 字为参考，复杂业务可调整，不能为了短而隐藏决定推荐是否适用的关键条件。段落通常不超过三行。不要照搬聊天长文，也不把所有内容塞进折叠区。

## 视觉

- 默认使用浅底、深色文字、一种强调色和充足留白；遵从用户品牌或风格要求。统一字体层级与图标语言，手机单列，桌面适当分栏。
- 至少使用两种有解释作用的视觉：例如瓶颈路径图＋实验时间线，或客户场景插图＋方法比较图。图中每个元素应对应真实分析，不能只堆 emoji 或装饰性图标冒充图文。
- 优先内联 SVG、CSS 绘图或 HTML 流程图，旁边附可读短文本。需要真实产品界面时仅用提供或核实的截图；概念示意必须明确标注，不能冒充产品真实功能。
- AI 剪辑软件可用“素材→AI 处理→人工确认→成片”的示意图解释验证路径，但只展示已知能力；未知能力用假设标签。
- 图表不依赖颜色单独传递含义；图示提供文字说明或可访问名称。兼顾文字对比度、键盘操作和减少动态效果的偏好。
- 外部链接使用真实可访问地址。匹配 skill 展示名称和用途；没有调用机制时不制作虚假的“运行 skill”按钮。不添加无效 CTA。

## 完成检查

确认文件已生成、页面能打开、结论和图示一致、假设与事实分明、来源可追溯。具备浏览器预览能力时检查桌面和手机宽度的溢出、文字裁切、图示可读性和折叠交互，并修复发现的问题。预览能力不可用时完成文件及内容检查，并在交付中说明未做浏览器验证，不声称已验证渲染。
